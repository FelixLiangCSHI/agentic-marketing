# ADR-006：外部写操作必须幂等并可对账

- 状态：Accepted
- 日期：2026-08-28
- 决策者：Architecture / Backend（待签字复核）

## 背景

队列至少一次投递、Worker 崩溃恢复和重试都会导致同一外部写操作被多次尝试。重复发布内容或重复创建 Campaign 是不可接受的业务与成本事故。

## 决策

- 每个 L2/L3 外部写操作携带确定性**幂等键**（由 run_id、task_id、操作类型与输入哈希派生）。
- Connector 在执行写之前必须检查幂等记录；重复投递的重复副作用必须为 0（阶段验收硬门）。
- 写操作完成后记录 external_object_id，并通过轮询（ADR-004）**对账**：本地意图状态与供应商实际状态定期比对，差异生成告警与人工处理项。
- 失败重试使用指数退避 + 抖动；超过最大重试进入 DLQ，Poison Message 隔离。
- 状态变化与审计写入同一事务或 Outbox；`run_events` 只追加。

## 后果

- Worker 可安全崩溃与重启（Checkpoint/Resume），不产生重复外部副作用。
- 对账为最终一致，需要容忍轮询延迟。

## 关联

ADR-003、ADR-004。
